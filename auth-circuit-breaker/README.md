# Прокси с Circuit Breaker для сервиса авторизации

Отдельный HTTP-сервис (контейнер), который стоит между клиентами и сервисом авторизации. В штатном режиме он просто проксирует запросы. Параллельно ведётся учёт сбоев.

## Запуск

- **Docker / образ:** [Gunicorn](https://gunicorn.org/) с воркером **`aiohttp.worker.GunicornWebWorker`** (штатный способ для `aiohttp.web` за мастер-процессом). Команда в `Dockerfile`.
- **Ровно один воркер** (`--workers 1`): счётчики и состояние прерывателя хранятся **в памяти процесса**. Несколько воркеров без общего хранилища дали бы независимые CB и непредсказуемое поведение.
- **Локально без Gunicorn:** `python -m src.main` — встроенный `web.run_app` с `LISTEN_HOST` / `LISTEN_PORT`. В контейнере порт фиксирован в `CMD` Gunicorn (`0.0.0.0:8000`).

## Состояния

| Состояние   | Поведение |
|------------|-----------|
| **CLOSED** | Запросы пересылаются в сервис авторизации. Подряд зафиксированные сбои считаются; при достижении порога — переход в **OPEN**. Успешный ответ (см. ниже) обнуляет счётчик сбоев. |
| **OPEN**   | Запросы **не** отправляются к сервису авторизации. Клиенту сразу возвращается 503. По истечении таймаута восстановления — переход в HALF-OPEN. |
| **HALF-OPEN** | Разрешено не более **`HALF_OPEN_PROBES`** запросов к сервису авторизации за одну «попытку» восстановления. Любой успешный ответ — переход в CLOSED. Любой сбой (см. ниже) — снова **OPEN**. Если квота проб исчерпана до успеха — следующие запросы до нового цикла восстановления получают отказ. |

## Политика «сбой» / «успех»

Считается **сбоем сервиса авторизации** (увеличивает счётчик в CLOSED или переводит в OPEN из HALF-OPEN):

- ошибки транспорта: таймаут, обрыв соединения, DNS, любые `aiohttp.ClientError`;
- HTTP-ответы с кодом **≥ 500** (включая 502/503/504 от auth-сервиса или прокси перед ним).

Считается **успехом** (обнуляет счётчик в CLOSED или переводит из HALF-OPEN в CLOSED):

- любой ответ с кодом **< 500** (в том числе **401**, **403**, **404** и т.д.) — сервис авторизации ответил и считается «живым» с точки зрения доступности.

## Параметры (переменные окружения)

| Переменная | Значение по умолчанию | Смысл |
|------------|----------------------|--------|
| `UPSTREAM_AUTH_BASE_URL` | — (обязательно) | Базовый URL auth-сервиса, например `http://authapi:8000` |
| `FAILURE_THRESHOLD` | `5` | Сколько **подряд** сбоев в **CLOSED** нужно для перехода в **OPEN** |
| `RECOVERY_TIMEOUT_SECONDS` | `30` | Секунд в **OPEN** до перехода в **HALF-OPEN** (проверка восстановления) |
| `HALF_OPEN_PROBES` | `1` | Максимум запросов к сервису авторизации в одной фазе **HALF-OPEN** |
| `REQUEST_TIMEOUT_SECONDS` | `60` | Таймаут HTTP-запроса к сервису авторизации |
| `LISTEN_HOST` | `0.0.0.0` | |
| `LISTEN_PORT` | `8000` | |

## Служебные эндпоинты

- **`GET /health`** — проверка самого прерывателя.

## Интеграция в проект

1. В Docker-сети сервисы, которые ходят в авторизацию, смотрят на этот контейнер вместо `authapi`, например **`AUTH_SERVICE_HOST=auth-circuit-breaker`** и порт **`8000`** (в том же `docker-compose` имя сервиса — `auth-circuit-breaker`).
2. **Nginx** в `configs/nginx/default.conf` проксирует префикс `/users/` на `auth-circuit-breaker:8000` вместо прямого `authapi`.
3. Внутренние URL клиентов с OpenAPI (например админка, `AUTH_API_URL`) при необходимости тоже можно переделать на `http://auth-circuit-breaker:8000`.

Прерыватель создается один раз, новые сервисы не реализуют свой прерыватель самостоятельно - просто направляют траффик на уже имеющийся.
